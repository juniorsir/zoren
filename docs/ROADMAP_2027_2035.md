# Zoren Evolution Roadmap (2027–2035)

This document outlines the official multi-year architectural evolution for the Zoren Programming Language, Compiler Platform, and Developer Ecosystem following the Zoren 1.0 Production Release.

---

## Zoren 1.1 — Developer Experience (DX)
*Target: Q2 2027*

Focus: Maximizing developer productivity and inner-loop compilation performance.

### Key Goals:
- **Sub-Millisecond Incremental Builds:** File-hash dependency caching avoiding redundant AST re-parsing.
- **Enhanced LSP Engine:** Sub-10ms response times for hover, completion, and definition queries in editors.
- **Smarter Linter:** Expanded static analysis warnings (`Z6xxx`) for unused parameters, dead assignments, and unoptimized allocations.
- **Rich Diagnostic Formatting:** Context-aware suggestion engines with automatic quick-fixes.

---

## Zoren 1.2 — Compile-Time Programming
*Target: Q1 2028*

Focus: Zero-runtime-overhead metaprogramming and build-time evaluation.

### Key Goals:
- **`comptime` Evaluation:** Execution of Zoren subroutines during compilation for constant expression calculation.
- **Build-Time Asset Embedding:** Safe embedding of external files, configurations, and raw bytes into binary data sections.
- **Compile-Time Validation:** Domain-specific static assertions evaluated before code generation.

---

## Zoren 1.3 — Controlled Reflection
*Target: Q4 2028*

Focus: Safe type inspection without compromising compiler optimizations.

### Key Goals:
- **Static Type Inspection:** Query field names, types, abilities, and model annotations at compile-time.
- **Zero-Cost Serialization:** Generic JSON/binary encoding generated without dynamic reflection overhead.
- **Runtime Type Information (RTTI):** Opt-in type tags for dynamic polymorphic dispatch.

---

## Zoren 1.4 — WebAssembly (Wasm) Architecture
*Target: Q3 2029*

Focus: Browser and serverless WASI target support.

### Key Goals:
- **Native Wasm Emission:** Direct AArch64/x86_64 to WebAssembly code generation target.
- **WASI System Interface:** File I/O, networking, and environment bindings conforming to WASI specifications.
- **DOM & JS Interop:** High-speed bindings for browser execution contexts.

---

## Zoren 1.5 — Embedded Systems & Bare-Metal
*Target: Q2 2030*

Focus: High-efficiency code generation for microcontrollers and IoT hardware.

### Key Goals:
- **Target Boards:** ARM Cortex-M, ESP32, Raspberry Pi Pico, STM32.
- **Zero-Allocation Mode:** Core runtime subset operating without dynamic heap allocation (`#no_heap`).
- **Deterministic Latency:** Microsecond-predictable execution timing for real-time applications.

---

## Zoren 1.6 — GPU Programming & Compute Kernels
*Target: Q2 2031*

Focus: Authoring high-performance compute kernels directly in Zoren syntax.

### Key Goals:
- **Compute Backends:** Vulkan, CUDA, Metal, DirectX.
- **Unified Kernel Syntax:** Expressing SIMD/vector parallel operations natively.
- **Host-Device Data Transfer:** Safe buffer abstractions managing GPU VRAM allocations.

---

## Zoren 1.7 — AI & Data Science
*Target: Q3 2032*

Focus: First-class high-performance numerical and machine learning primitives.

### Key Goals:
- **`std/tensor` Package:** Multi-dimensional contiguous tensor models with SIMD vectorization.
- **Automatic Differentiation:** Compile-time reverse-mode autograd for gradient computation.
- **Hardware Acceleration:** Native NPU/Tensor Core acceleration hooks.

---

## Zoren 2.0 — Enterprise Edition & Cloud Runtime
*Target: 2035*

Focus: Scalable distributed systems and long-term enterprise compatibility.

### Key Goals:
- **Distributed Actor Runtime:** Transparent location-agnostic actor message passing across clusters.
- **Cloud-Native Services:** Integrated distributed tracing, metrics, and security sandboxing.
- **Long-Term Support (LTS):** Guaranteed 10-year stable ABI and language specification backward compatibility.
- **RFC Governance Process:** Community-driven Request for Comments pipeline governing all language changes.

---

## Long-Term Vision Metrics

The long-term trajectory of Zoren is measured by:
1.  **Reliability:** Zero undefined behavior, explicit error contracts, and deterministic scope cleanup.
2.  **Simplicity:** Expressive non-abbreviated vocabulary (`bind`, `flex`, `bring`, `flow`, `deliver`, `model`, `ability`, `grant`, `ensure`).
3.  **Performance:** Zero-cost abstractions, compile-time monomorphization, and direct bare-metal assembly code generation.
4.  **Developer Happiness:** Fast tooling, helpful diagnostic stories, and integrated editor support.
